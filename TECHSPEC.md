# ТЗ: устранение хроматической аберрации (стадия 3)

Зафиксировано 31.10.2026. Источник: сводка требований заказчика/наставника + результаты
экспериментов над defringe v2.1 (коммиты dbcb79d, b250ee8). Домен и текущее состояние — `CONTEXT.md`.

Суть: не «подкрутить силу defringe», а объяснить, почему кайма остаётся, и устранить её
подходящим для каждого типа дефекта механизмом, доказав тестами, что ничего полезного не
испорчено. Буквальное отсутствие цветовых отклонений на каждом пикселе недостижимо (шум,
JPEG, естественные переходы), цель — отсутствие видимой искусственной каймы при
максимальном сохранении исходной информации.

## 2. Проблема 1: остаточная кайма на detail_ca (P1)

Проявления: (а) основная голубая граница вокруг светлого объекта ослаблена, но не убрана;
(б) тонкий синий контур вдоль отдельных участков границы; (в) длинный цветной хвост,
который не захватывает локальная коррекция с малым радиусом.

Два механизма, которые могут присутствовать одновременно:
- поперечная CA — пространственное смещение каналов (синяя кайма с одной стороны контура,
  другая с противоположной);
- продольная CA — разная резкость каналов, цветные ореолы без смещения.

Гипотезы о слабых местах текущей реализации (требуют подтверждения при аудите, не факты):
1. Радиус обработки не покрывает ширину ореола.
2. Зависимость от яркого белого ядра — маска формируется неверно на полупрозрачных границах.
3. Ошибка оценки направления/фона на сложном фоне.
4. Слишком жёсткая цветовая маска — слабую кайму не проходит порог.

Усиление силы фильтра решением не является: начнёт удалять настоящие цветные детали и
размывать резкость.

## 3. Проблема 2: кайма на тонких стебельках розового цветка (P2)

Отдельная задача, не решается тем же способом, что белый цветок. Сложности:
- стебельки розово-пурпурные: синий компонент — естественная часть цвета;
- ширина объекта 1–5 px: участок содержит одновременно цвет стебля, сглаживание, кайму,
  фон и противоположную сторону объекта — цветовая маска ненадёжна.

Гипотеза механизма: локальное субпиксельное смещение синего канала относительно R/G на
границе. Требуется оценивать несоответствие положений цветовых границ, а не абсолютный
синий избыток. Исправление: локальная субпиксельная регистрация каналов:
границы → нормаль к контуру → профиль каждого канала перпендикулярно границе →
субпиксельная оценка положения границы → обнаружение действительного смещения →
коррекция только смещения → плавное смешивание. Обе стороны тонкого объекта учитываются;
глобальный сдвиг всего синего канала запрещён (пострадают настоящие синие/фиолетовые детали).

## 4. Проблема 3: увеличенные фрагменты/вставки (P2–3)

Источники ошибки: масштаб (радиусы в пикселях не масштабируются), интерполяция при
увеличении (усиливает слабую кайму), порядок обработки (где в конвейере создаётся вставка
и когда считается коррекция — подтвердить в коде `app.py`).

Целевой конвейер: глобальная коррекция каналов → локальная коррекция остаточной каймы →
создание увеличенных фрагментов → контрольный проход на увеличенном изображении
(только если найдены артефакты интерполяции) → финальная композиция. Без повторных
коррекций (накопление искажений). Радиусы/пороги масштабируются по коэффициенту увеличения.
Рамка вставки, подписи, декор — нетронуты.

## 6. Целевая архитектура (модули)

| Модуль | Задача | Соответствие текущему коду |
| --- | --- | --- |
| A. Глобальная коррекция каналов | Систематическое смещение, радиальная модель Δr = k1·r + k2·r³ (с допущением более гибкого поля для сложной оптики) | частично уже есть: `auto.py` (коррекция авто) + `local.py` (поле смещений по сетке); сверить модель и её связь с радиусом при аудите |
| B. Локальная коррекция контуров | Модель смешивания C = α·F + (1−α)·B: оценивать отклонение от ожидаемого смешивания, а не вычитать синий; работа в линейном RGB | `defringe.py` — fg-ratio модель (v2.1) уже близка по идее; сверить гамму (текущая — в sRGB) и охват хвостов |
| C. Тонкие цветные объекты | Субпиксельная регистрация по краям, защита цвета | нового нет; проверить поведение при ширине 1/2/3/5 px |
| D. Увеличенные области | Определение вставки, её масштаба, повторная коррекция при необходимости, исключение рамок/подписей | построение вставок в `app.py` — подтвердить порядок операций |
| E. Финальный контроль | Детектирование остаточной каймы без автоматической правки; передача на нужный этап | нового нет |

Каждый механизм включается только при наличии соответствующего типа дефекта
(автоматика включения — отдельное требование).

## 8. Метрики и критерии приёмки

1. Смещение каналов: субпиксельные положения границы на канал, D_RB, D_GB — должны падать.
2. Кайма: ΔE00 (CIE Lab) вокруг границы + метрика синего избытка.
3. Сохранение цвета: ΔE на участках, не подлежащих коррекции (стебельки, настоящие синие).
4. Сохранение резкости: ширина перехода на контуре; размытие не засчитывается как успех.

Критерии приёмки: уменьшение измеряемого смещения (обязательно); отсутствие каймы
противоположного цвета (обязательно); сохранение настоящих синих деталей (обязательно);
сохранение резкости контуров (обязательно); отсутствие ухудшения на линзе (обязательно).
