обработки от разрешения.

## Физическая модель

- **Латеральная CA**: каналы R и B радиально смещены относительно опорного G;
  смещение d(r) растёт от оптического центра (центр кадра — текущее приближение).
- Калибровочный режим: модель d(r) = c1·r + c2·r² + c3·r³ (полином без свободного члена).
- Слепой режим: d(r) = k·r, линейная, как в Lightroom — полином высших степеней
  на шумных краях реальных фото экстраполирует нефизично.
- **Продольная CA** (R/B расфокусированы, а не смещены) варпом не лечится в принципе —
  это честно отражено в ограничениях, не баг.

## Архитектура и публичные швы (`achrom/`)

| Модуль | Шов | Что делает |
|---|---|---|
| `calibration.py` | `detect_dots(gray)` | центроиды точек калибровочного кадра |
| | `measure_displacements(frame, center)` | (r, dr_red, dr_blue) по кадру с точками |
| | `fit_radial(r, d, degree=3)` | МНК полинома d(r) без свободного члена |
| | `radial_model(coeffs, r)` | вычислить d(r) |
| `blind.py` | `estimate_displacements_blind(frame, center, degree=1)` | (r, dr_red, dr_blue) по краям самого снимка: Sobel-края перпендикулярно радиусу (cos > 0.7), NCC по радиальным профилям ±24px, параболическая субпиксельная доработка, отбраковка остатков >1px |
| `correction.py` | `correct(frame, center, coeffs_red, coeffs_blue)` | обратный варп R и B к G (фиксированная точка, 3 итерации, BORDER_REPLICATE) |
| `metrics.py` | `channel_residual(frame, center)` | (mean, max) расхождения каналов по точкам |
| `benchmark.py` | `benchmark(coeffs_r, coeffs_b, sizes)` | [(w, h, ms)] время коррекции от разрешения |
| `synthetic.py` | `make_dot_frame(...)`, `apply_radial_shift(...)` | генератор кадров с известной аберрацией (тест-инфра + демо) |

`app.py` — GUI (tkinter), единственная кнопка «Загрузить снимок»: слепая
автокоррекция в фоне (3 итерации, автостоп <0.5px). Результаты пишутся в
`results/<имя_снимка>_{before,after,diff}.png`, diff (углы до/после рядом)
открывается в системном просмотрщике (Tk на этой машине битмапы не рендерит,
см. «Открытые проблемы»). Калибровка по мишени, демо и замер времени из GUI
убраны за ненадобностью — калибровочный шов остаётся в `achrom/calibration.py`
(покрыт тестами, материал для РПЗ). ГЛАВНОЕ: калибровочные коэффициенты
привязаны к размеру кадра мишени — применять их к фото другого размера нельзя
напрямую (экстраполяция куба даёт бред); слепой режим этим не страдает,
он всегда меряет в пикселях самого снимка. `test_window.py` — диагностика
рендера Tk.

## Режимы (оба — часть работы, сравниваются в РПЗ)

1. **По калибровочному кадру** (чёрные точки на белом): detect_dots в каждом канале →
   матчинг ближайших → проекция смещения на радиус → фит.
2. **Слепой** (без калибровки, как фотошоп): края самого снимка служат калибровкой.
   Итеративно: измерил → исправил → перемерил (до 3 проходов, автостоп).

## Данные (`data/`)

- `real_macro_ca.jpg` — Wikimedia Commons, Canon PowerShot SX540 HS, 5184×2912,
  реальная латеральная CA: R −8.65px, B +10.91px на краю. Главный тест-кейс.
- `real_blende8.jpg` — Nikon D90, 2000×1328, JPEG с внутрикамерной коррекцией —
  контроль ложных срабатываний (должно быть «CA < 0.5px, не требует коррекции»).
- `blur.png` — дифракционный объектив (KAUST,
  CC BY-NC): продольная CA, латеральный сдвиг ≈0 — пример нерешаемого варпом случая.
- `lens_ca.jpg` — Wikimedia Commons, «ChromaticAberrationInLens.jpg», Willm2028,
  CC BY-SA 4.0, 2462×2532. Сильная поперечная CA: **R −8.07px, B +14.01px** на краю;
  слепая коррекция за 2 итерации → остаток **R −0.01, B +0.14px**. Второй сильный кейс.
- `holga_tatra.jpg` — «Tatra car (holga).jpg», Jakub T. Jankiewicz, CC BY-SA 3.0,
  3840×2566 (thumb с Commons; оригинал 5736×3833). Снято игрушечной Holga без
  коррекции: R −2.24px, B +2.71px → остаток −0.09/+0.19px за 1 итерацию.
- `detail_ca.jpg` — «Chromatic aberration with detail.jpg», Jkk, CC BY-SA 3.0,
  2592×2592. Слабый/умеренный случай: R −1.04px, B +2.08px → остаток −0.28/+0.25px.
- Источник: категория Chromatic aberration на Wikimedia Commons (свободные лицензии).

Важно: современные фото на Commons (серия Dülmen/Haltern и т.п.) уже прошли
автокоррекцию CA в Lightroom — слепой оценщик даёт на них ≈0.00px. Для сильных
кейсов нужны некорректированные кадры: старые мыльницы, игрушечная/советская оптика.

## Измеренные результаты (для РПЗ)

- Синтетика 500px, k=±8%/6%: расхождение 11.92px → 0.83px (макс 24.88 → 1.80) по калибровке;
  слепой режим восстанавливает модель с точностью <0.15px (R +15.93 при истине +16.0).
- Реальное макро (5184×2912): R −9.7/B +15.6px устранён за 3 итерации, остаток −0.39/+0.69px, 2.0с.
- `lens_ca.jpg`: R −8.07/B +14.01px → −0.01/+0.14px за 2 итерации, 0.7с @2462×2532.
- `holga_tatra.jpg`: R −2.24/B +2.71px → −0.09/+0.19px за 1 итерацию, 0.6с @3840×2566.
- `detail_ca.jpg`: R −1.04/B +2.08px → −0.28/+0.25px за 1 итерацию, 0.3с @2592×2592.
- `real_blende8.jpg`: −0.11/+0.22px — ниже порога 0.5px, коррекция не требуется.
- Время коррекции растёт линейно (~55мс/Мпикс): 24.5мс @640×480 … 614мс @3840×2880.

## Открытые проблемы

- **Рендер битмапов в Tk не работает на машине пользователя**: test_window.py
  (голое окно, красный квадрат через ImageTk и зелёный через нативный PPM)
  показывает пустое окно — системный Tcl/Tk из CommandLineTools не рисует
  картинки вообще. Поэтому показ результата переведён в системный
  просмотрщик: `_display` делает `open result_zoom.png` (Preview), в окне —
  только кнопки и статус с полными путями к PNG. Если появится Python
  с нормальным Tk (python.org / Homebrew), панели можно вернуть.
- Побочное: в headless-прогонах агента Tk-панели геометрически «принимают»
  картинки, но визуально проверить нельзя — выводы о «работает» делать
  только по файлам и логам, не по GUI.

## Ограничения (честные, для РПЗ и защиты)

- Продольная CA не корректируется (нет параллакса для измерения).
- Оптический центр = геометрический центр кадра; оценка центра по точкам не делалась.
- JPEG из камер с включённой внутрикамерной коррекцией → «CA не обнаружена» (валидация,
  не провал).
- Остаточный рассинхрон на краях после коррекции макро (~59 яркостей) — вклад продольной
  CA и JPEG-артефактов.
