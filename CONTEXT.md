## Физическая модель

- **Латеральная CA**: каналы R и B радиально смещены относительно опорного G;
  смещение d(r) растёт от оптического центра (центр кадра — текущее приближение).
- Калибровочный режим: модель d(r) = c1·r + c2·r² + c3·r³ (полином без свободного члена).
- Слепой режим: d(r) = k·r, линейная, как в Lightroom — полином высших степеней
  на шумных краях реальных фото экстраполирует нефизично.
- **Продольная CA** (R/B расфокусированы, а не смещены) варпом не лечится в принципе —
  это честно отражено в ограничениях, не баг.

## Архитектура и публичные швы (`achrom/`)

| Модуль | Шов | Что делает |
|---|---|---|
| `calibration.py` | `detect_dots(gray)` | центроиды точек калибровочного кадра |
| | `measure_displacements(frame, center)` | (r, dr_red, dr_blue) по кадру с точками |
| | `fit_radial(r, d, degree=3)` | МНК полинома d(r) без свободного члена |
| | `radial_model(coeffs, r)` | вычислить d(r) |
| `blind.py` | `estimate_displacements_blind(frame, center, degree=1)` | (r, dr_red, dr_blue) по краям самого снимка: Sobel-края перпендикулярно радиусу (cos > 0.7), NCC по радиальным профилям ±24px, параболическая субпиксельная доработка, отбраковка остатков >1px |
| `correction.py` | `correct(frame, center, coeffs_red, coeffs_blue)` | обратный варп R и B к G (фиксированная точка, 3 итерации, BORDER_REPLICATE) |
| `metrics.py` | `channel_residual(frame, center)` | (mean, max) расхождения каналов по точкам |
| `benchmark.py` | `benchmark(coeffs_r, coeffs_b, sizes)` | [(w, h, ms)] время коррекции от разрешения |
| `synthetic.py` | `make_dot_frame(...)`, `apply_radial_shift(...)` | генератор кадров с известной аберрацией (тест-инфра + демо) |

`app.py` — GUI (tkinter), единственная кнопка «Загрузить снимок»: слепая
автокоррекция в фоне (3 итерации, автостоп <0.5px). Результаты пишутся в
`results/<имя_снимка>_{before,after,diff}.png`, diff (углы до/после рядом)
открывается в системном просмотрщике (Tk на этой машине битмапы не рендерит,
см. «Открытые проблемы»). Калибровка по мишени, демо и замер времени из GUI
убраны за ненадобностью — калибровочный шов остаётся в `achrom/calibration.py`
(покрыт тестами, материал для РПЗ). ГЛАВНОЕ: калибровочные коэффициенты
привязаны к размеру кадра мишени — применять их к фото другого размера нельзя
напрямую (экстраполяция куба даёт бред); слепой режим этим не страдает,
он всегда меряет в пикселях самого снимка. `test_window.py` — диагностика
рендера Tk.

## Режимы (оба — часть работы, сравниваются в РПЗ)

1. **По калибровочному кадру** (чёрные точки на белом): detect_dots в каждом канале →
   матчинг ближайших → проекция смещения на радиус → фит.
2. **Слепой** (без калибровки, как фотошоп): края самого снимка служат калибровкой.
   Итеративно: измерил → исправил → перемерил (до 3 проходов, автостоп).

## Обновление: robust-автокоррекция (`achrom/auto.py`)

- `correct_auto(frame)` заменяет цикл «оценка → варп → оценка» из `app.py`: края равномерно по сетке (NMS, веса по контрасту), измерение сдвига по профилям вдоль нормали (корреляция производных, параболическое субпиксельное уточнение), модель на канал = сдвиг + радиальный полином (a1, a3) + нуисанс-смещение, IRLS (Tukey) с байесовским ridge. Накопленная модель, ОДИН варп оригинала (`INTER_CUBIC`) — R/B больше не ресемплируются по 3 раза.
- Остановка по шуму замера: если приращение p95 < 0.12 px — не варпим. Чистый кадр остаётся байт-в-байт.
- Статус в GUI теперь содержит реальный повторный замер (`residual`), а не зашитое «<0.7px».
- `suppress_glare` по умолчанию ВЫКЛЮЧЕН (`SUPPRESS_GLARE` в app.py): это не коррекция CA, а замена синего канала; на `detail_ca` оставляет зелёную полосу.
- Валидация — на синтетике с известной истиной (стенд вне репозитория): ошибка вдвое ниже прежнего пайплайна.
- Известно: `detail_ca.jpg` содержит вставку-увеличение (врезка) и широкое синее свечение (продольная CA/blooming) — варпом не лечится; `lens_ca.jpg` — радужный блик, оценка там неоднозначна.

## Обновление: локальная регистрация (`achrom/local.py`)

- Проблема `detail_ca.jpg`: края каналов идут ступенькой (R ≈ y2320, G ≈ y2335, B ≈ y2350 на полном разрешении) — синий край сдвинут наружу на ~20 px и размыт. Глобальной радиальной моделью это не описать.
- `local_register(frame)`: по сильным нейтральным краям (контраст ≥ 70, одинаковый знак градиента во всех каналах) измеряется сдвиг R/B вдоль нормали (пирамида 1/4 → 1/2 → 1/1, сдвиги до ±160 px на грубом масштабе), поле нормированной сверткой и применяется только там, где ≥3 края со сдвигом ≥1.5 px. Нулевые края работают якорями. Остальные пиксели байт-в-байт прежние (тест `test_far_from_edges_is_byte_identical`).
- Ограничения: остаётся тонкий тёмно-зелёный контур (хвост G шире хвостов R/B) и кусок синего у рамки врезки; цветные края (синий объект) не трогаются.

## Обновление: дефринж (`achrom/defringe.py`) вместо сдвига для широкой каймы

- Почему не сдвиг: широкое синее свечение у светлых областей — не смещение, а размытая «юбка» канала B (продольная CA). Сдвиг её переносит и даёт коричневые/синие полосы («как маркером»).
- Алгоритм: светлые «чистые» пиксели (G≥200, нейтральные) и тёмный чистый фон → локальные цвета лепестка и фона нормированной сверткой. Для пикселя в переходной зоне (рядом и светлое, и фон, dist_fg+dist_bg ≤ 7% короткой стороны) прозрачность α берётся из G, ожидаемое смещение канала (C−G) интерполируется между фоном и лепестком; R/B подтягиваются к ожидаемому там, где отклонение > 22…65 уровней, только для сине-голубых отклонений (B ≥ G−5).
- Не меняет: нейтральные пиксели, чёрную рамку, синие объекты вдали от светлого, всё вне зоны (тесты в `tests/test_defringe.py`).
- Конвейер в app.py: `correct_auto` → `defringe`. `local_register` оставлен, но выключен (`LOCAL_REGISTER=False`): на широких каймах даёт «кривые» края.
- Результат на `detail_ca.jpg`: пикселей с избытком синего >30: 105 903 → 2; затронуто ~2.8% кадра. Остаются слабые голубые ободки на расфокусированных лепестках.

## Обновление: defringe v2 — fg-ratio модель + evid-гейт (`achrom/defringe.py`)

- Диагноз остаточных ободков v1: (1) аддитивная модель (C−G) не видит, что юбка B масштабируется с яркостью (отношение, а не офсет); (2) ожидание для яркого содержимого форсирует нейтраль — синеватые облака holga тянутся к серому, небо «сэндвичем» между яркими и тёмными облаками (24.8% кадра) корректируется без причины; (3) рампа |d|>22 без доказательства каймы стреляет по любому рассогласованию модели.
- Модель v2: ожидание канала C = G·(rc + (rf − rc)·α), где rc/rf — локальные отношения C/G фона и светлого (нормированная свертка, σ = reach), α — прозрачность из G. Юбка масштабируется с яркостью, цвет яркого содержимого (голубоватые облака) сохраняется.
- Доказательство каймы (evid): вдоль ∇dist (от светлого) на reach/3 сэмплируется b_far; evid = clip((B − b_far − 8)/20). Реальная юбка затухает от источника → evid высокий; гладкое небо/плато → evid ≈ 0. Единый гейт: m = evid·max(gentle, sharp) — без затухания синего от источника никакая рампа не стреляет.
- Рампы: gentle |d| 22→65; sharp B при d>0: 4→20; sharp R при d<0: 8→36; smoothstep + гейты prox·valid·near·(G≥Gb−15)·(B≥G−5).
- Контрольные кадры (циан = B−R≥20 & B−G≤15, после `correct_auto`):
  - `detail_ca`: bbox каймы B−R>60: 23797 → 10; циан 54101 → 16145; changed 3.09%. Кроп каемки: циан 6.85% → 2.12% (v1 давал 9.11% — ухудшал).
  - `holga_tatra`: открытое небо не трогается (контрольные пиксели [130,173,217] и [72,103,120] байт-в-байт); правки только у ободков облаков с реальным затуханием B (evid=1), changed 3.84%. Метрика циана на holga малоинформативна: небо естественно «циановое» (382k до коррекции), частичное обесцвечивание ободков меняет счётчик, но не открытое небо.
  - `real_blende8`: changed 3.13% (v1: 0.78%, base v2 без гейта: 8.86%) — каймы боке правятся умеренно.
